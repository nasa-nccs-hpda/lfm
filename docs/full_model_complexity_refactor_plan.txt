Full-Model Complexity Refactor Plan
===================================

Purpose
-------

This document tracks the next cleanup phase for the active full-model semantic
and instance segmentation workflows.

The repo has already moved notebook-adjacent scripts into scripts/python and
scripts/shell. The next problem is that several active files now contain too
many responsibilities: plotting, prediction caching, metrics, callbacks,
configuration, model setup, datamodule setup, trainer setup, and CLI entrypoints
are mixed together.

Use this plan when breaking large active workflow files into smaller importable
modules while preserving current behavior.


Current High-Complexity Files
-----------------------------

Highest-priority refactor targets:

- lfm/full_model/utils/plot_utils.py
  - Around 1400+ lines.
  - Mixes semantic plotting, instance plotting, prediction caches, metrics,
    display helpers, label comparison plots, and Lightning callbacks.

- scripts/python/instance_seg_comparison.py
  - Around 600+ lines.
  - Mixes CLI parsing, config construction, Toy setup, Graha setup, callbacks,
    training orchestration, plotting, and final comparison.

- scripts/python/semantic_seg_comparison.py
  - Around 600 lines.
  - Mixes CLI parsing, config construction, Toy semantic training, Graha
    semantic training, timing, prediction caching, metrics, and plotting.

- scripts/python/instance_seg_finetuning.py
  - Around 500+ lines.
  - Mixes environment setup, config, datamodule creation, task creation,
    trainer creation, checkpoint loading, plotting, and CLI parsing.

Medium-priority targets:

- lfm/full_model/semantic_seg_finetuning.py
  - Semantic Graha finetuning equivalent.
  - Should eventually mirror the same structure as instance finetuning.

- lfm/toy_model/inst_seg/iseg_driver.py
  - Large older toy instance driver.
  - Refactor only if we continue to maintain it directly. Otherwise, extract
    useful plotting/metric behavior and leave the old driver stable.

- lfm/toy_model/inst_seg/iseg_dataset.py
  - Dataset plus statistics/dataloader helpers.
  - Lower priority than active comparison and finetuning workflows.

Avoid broad refactors for now:

- lfm/full_model/graha-lunar-fm/terramind/*
- Most vendor-style Graha/TerraTorch integration code

Those files are large, but they are not the best first cleanup target unless a
specific bug forces a focused change.


Target Structure
----------------

Proposed package modules:

```
lfm/full_model/
  all_tasks/
    callbacks.py
    config_utils.py
    timing_utils.py
    checkpoint_utils.py
    path_utils.py

  utils/
    display.py
    metrics.py
    prediction_cache.py
    sem_seg_plotting.py
    inst_seg_plotting.py

  sem_seg/
    comparison.py
    finetuning.py
    checkpoint_sweep.py

  inst_seg/
    comparison.py
    finetuning.py
```

Script entrypoints should remain under:

```
scripts/python/
scripts/shell/
```

Notebook entrypoints should remain under:

```
notebooks/full_model/
```


Refactor Principles
-------------------

- Preserve behavior first; reduce duplication second.
- Move code mechanically before changing logic.
- Keep CLI scripts thin: argparse, config construction, call package function.
- Keep notebooks linear and user-facing, but make them import the same package
  functions as scripts.
- Keep shared plotting/cache behavior in package modules so Toy and Graha plots
  cannot drift.
- Do not refactor vendor/TerraMind code broadly during this cleanup.
- After each step, run lightweight checks before moving on.
