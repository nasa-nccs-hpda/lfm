Segmentation Data And Workflow Refactor Plan
===========================================

Purpose
-------

This document captures a feasible refactor direction for reducing duplicated
semantic segmentation and instance segmentation workflow code while preserving
the repository's symmetry goals.

Core Refactor Constraints
------------------------

- Maintain Toy vs Graha symmetry whenever it does not reduce functionality.
- Maintain semantic segmentation vs instance segmentation symmetry whenever task
  differences do not require different structure.
- Avoid compatibility-only files. If code moves, update imports and references
  directly, then remove the obsolete location.
- Treat the eventual package structure as a three-axis separation:
  shared-across-models, full/Graha-specific, and Toy-specific.
- Use clean inheritance only at stable specialization boundaries, such as
  semantic-vs-instance target formatting.
- Prefer composition for behavior that varies independently, such as
  normalization, nodata handling, modality registration, plotting, checkpointing,
  trainer construction, and workflow orchestration.

Current Recommended Direction
-----------------------------

The overall direction is feasible: separate task data, model family behavior,
and experiment orchestration into explicit objects/modules instead of letting
scripts glue all behavior together.

The highest-value first target is the data layer, especially Toy semantic data
loading. This is where duplicated image loading, band filtering, normalization,
spatial transforms, label matching, and nodata behavior create avoidable churn.

Recommended Structure, Phased
-----------------------------

Eventual Target Package Structure
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The long-term package target is:

`lfm/lfm/all_models/all_tasks/`
`lfm/lfm/all_models/sem_seg/`
`lfm/lfm/all_models/inst_seg/`

`lfm/lfm/full_model/all_tasks/`
`lfm/lfm/full_model/sem_seg/`
`lfm/lfm/full_model/inst_seg/`

`lfm/lfm/toy_model/all_tasks/`
`lfm/lfm/toy_model/sem_seg/`
`lfm/lfm/toy_model/inst_seg/`

Ownership rules:

- `all_models/all_tasks`: shared across Toy and Graha, and shared across
  semantic segmentation and instance segmentation.
- `all_models/sem_seg`: shared across Toy and Graha, but specific to semantic
  segmentation.
- `all_models/inst_seg`: shared across Toy and Graha, but specific to instance
  segmentation.
- `full_model/all_tasks`: shared across semantic and instance segmentation, but
  specific to Graha/full-model behavior.
- `toy_model/all_tasks`: shared across semantic and instance segmentation, but
  specific to Toy behavior.
- `full_model/{sem_seg,inst_seg}` and `toy_model/{sem_seg,inst_seg}`:
  model-family-specific and task-specific implementation details.

This structure should be introduced gradually. Avoid creating empty mirrored
directories solely for symmetry. Prefer moving code when there is a concrete
shared behavior to extract.

Object-Oriented Design Target
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

The desired design should use shallow inheritance for stable structural
boundaries and composition for behaviors that vary independently.

Inheritance should cover:

- Dataset shape:
  - `BaseLunarSegmentationDataset`
  - `SemanticSegmentationDataset`
  - `InstanceSegmentationDataset`
- DataModule shape:
  - `BaseLunarSegmentationDataModule`
  - `SemanticSegmentationDataModule`
  - `InstanceSegmentationDataModule`
- Workflow/model adapter shape, later:
  - `BaseWorkflow`
  - `ToyWorkflow`
  - `GrahaWorkflow`
  - `BaseModelAdapter`
  - `ToySemanticModelAdapter`
  - `GrahaSemanticModelAdapter`
  - `ToyInstanceModelAdapter`
  - `GrahaInstanceModelAdapter`

Composition should cover:

- `ImageReader`
- `LabelReader`
- `PairMatcher`
- `NormalizationStrategy`
- `NoDataPolicy`
- `SpatialTransform`
- `TargetFormatter`
- `CollatePolicy`
- `Plotter`
- `PredictionCache`
- `CheckpointPolicy`
- `TrainerFactory`

Avoid inheritance trees that combine independent axes. Do not create classes
such as `ToyNacSemanticDataset` or `GrahaWacInstanceDataset` unless there is a
real model-family-specific behavioral boundary that cannot be expressed through
composition.

The near-term data package target is:

`all_models/all_tasks/data/base_dataset.py`
`all_models/all_tasks/data/base_datamodule.py`
`all_models/all_tasks/data/image_io.py`
`all_models/all_tasks/data/normalization.py`
`all_models/all_tasks/data/nodata.py`
`all_models/all_tasks/data/image_crop_resize.py`
`all_models/all_tasks/data/tensor_utils.py`
`all_models/all_tasks/data/collate.py`

`all_models/sem_seg/semantic_dataset.py`
`all_models/sem_seg/semantic_datamodule.py`

`all_models/inst_seg/instance_dataset.py`
`all_models/inst_seg/instance_datamodule.py`
`all_models/inst_seg/instance_data_utils.py`

Phase 2: Shared Dataset Path

Introduce a shared segmentation dataset base:

`BaseLunarSegmentationDataset`

This should handle image-side behavior once. Semantic and instance datasets
should only specialize target formatting:

- Semantic target output: `{"image", "mask", "filename"}`
- Instance target output: `{"image", "boxes", "masks", "labels", ...}`

Use inheritance only for the semantic-vs-instance target formatting boundary.
Use composition for behavior that varies independently.

Sub-steps:

1. Define `BaseLunarSegmentationDataset`.

   It should own the common sample lifecycle:

   - pair image and label paths
   - read image data
   - read raw label data
   - convert image layout
   - apply band filtering
   - apply nodata image policy
   - apply normalization strategy
   - apply spatial transform
   - return a prepared sample dict

   It should not decide final semantic-vs-instance target structure.

2. Define `SemanticSegmentationDataset(BaseLunarSegmentationDataset)`.

   It should specialize:

   - semantic label validation
   - semantic mask conversion
   - semantic ignore-index handling
   - semantic output formatting

3. [Completed] Define `InstanceSegmentationDataset(BaseLunarSegmentationDataset)`.

   It should specialize:

   - `.npz` instance label validation
   - instance mask conversion
   - box conversion/cropping
   - object-detection target formatting
   - instance output formatting

   `lfm.all_models.inst_seg.InstanceSegmentationDataset` now owns the shared
   split instance-label loading path used by Toy Mask2Former and Toy Mask R-CNN.
   It currently inherits from the all-task `LunarSegmentationDataset` base; the
   planned `BaseLunarSegmentationDataset` rename remains a later naming cleanup.

4. [Completed] Migrate Toy semantic first.

   The existing `LunarCraterDataset` can either become a thin subclass of
   `SemanticSegmentationDataset` if its name must remain temporarily, or be
   replaced directly if all imports can be updated in one step.

5. [Completed] Migrate Toy instance second.

   This is higher risk than semantic because it needs box/mask target behavior
   and object-detection collate semantics.

   Toy instance datamodules now instantiate
   `lfm.all_models.inst_seg.InstanceSegmentationDataset`, and Toy Mask R-CNN
   subclasses it for object-detection target formatting.

6. [Completed] Extract shared Toy instance datamodule mechanics.

   `lfm.all_models.inst_seg.instance_datamodule.InstanceSegmentationDataModule`
   now owns the duplicated split setup, dataset construction, optional train
   statistics, and dataloader creation used by the Toy Mask2Former and Toy
   Mask R-CNN instance datamodules. The Toy classes remain real
   specializations: they supply Toy input metadata behavior, and Mask R-CNN
   supplies its object-detection dataset, collate function, and stats key.

7. [Completed] Align Toy wrapper split layout and nodata composition.

   Toy Lightning wrapper data paths should use the same pre-split folder
   structure expected by the repo-owned full-model/Graha datamodules:

   `data_root/train/chips`
   `data_root/train/labels`
   `data_root/val/chips`
   `data_root/val/labels`
   `data_root/test/chips`
   `data_root/test/labels`

   Keep older legacy helper code stable, but route active Toy wrapper paths
   through composed `NoDataPolicy` behavior where they use shared datasets.
   Toy semantic already used this split-folder wrapper shape. Toy instance now
   validates the same split-folder structure, threads `NoDataPolicy` through
   the shared instance datamodule, applies nodata-aware image/mask handling in
   the shared instance dataset, and skips non-positive instance IDs when
   building Mask2Former targets.

8. [Completed] Review Graha semantic and instance datasets after Toy paths are stable.

   Do not touch `lfm/full_model/graha-lunar-fm`. Only migrate repo-owned Graha
   wrapper/datamodule code where behavior clearly overlaps.

   Repo-owned full-model datamodules now compose shared all-model helpers for
   split-folder layout resolution and nodata-policy construction while
   preserving TerraTorch-specific output contracts and legacy flat-layout
   support. Full inheritance from the `all_models` dataset/datamodule base is
   intentionally deferred until the shared base can express both Toy and Graha
   constructor/output contracts without forcing task-specific behavior into the
   wrong layer.

Phase 3: Normalization Strategy Objects

Introduce composable normalization strategies:

- `NoNormalization`
- `FinetuneStatsNormalization`
- `PretrainYamlNormalization`

Both Toy and Graha workflows should request normalization through the same
interface. The strategy can hide whether stats come from train-split data,
TerraMind pretraining YAML, or no normalization.

Sub-steps:

1. [Completed] Keep the shared interface simple:

   `NormalizationStrategy.apply(image, *, band_filter) -> image`

   The strategy interface also supports CHW tensors through
   `NormalizationStrategy.apply_tensor(image, *, band_filter=None) -> image` so
   older datamodule paths can use the same composition object before all dataset
   classes are unified.

2. [Completed] Use concrete strategy objects:

   - `NoNormalization`
   - `FinetuneStatsNormalization`
   - `PretrainYamlNormalization`

3. [Completed] Move ad hoc normalization calls out of dataset/datamodule code
   as each path migrates.

   The current Toy semantic, Toy instance, and repo-owned Graha datamodule paths
   now compose a normalization strategy while preserving existing `means`/`stds`
   constructor arguments.

4. [Completed] Keep modality-specific stats selection outside the dataset. The
   workflow or model adapter should decide which normalization strategy to pass
   in.

   TerraMind pretraining-stat loading now lives with shared normalization code
   under `lfm.all_models.all_tasks.data.normalization`, and active Toy/Graha
   workflows import it directly from that shared layer. The full-model utility
   package re-exports the same functions for older callers, but no shared
   `all_models` normalization code depends on `full_model`.

Phase 4: Shared Nodata Policy

Introduce a shared nodata preprocessing policy, for example:

`NoDataPolicy(ignore_in_loss=True, ignore_index=-1, image_fill_value=0.0)`

The dataset should apply image-side nodata behavior once. Losses and metrics
should consume the same `ignore_index` so masking semantics stay consistent.

Sub-steps:

1. [Completed] Keep nodata detection in image IO or preprocessing utilities.

2. [Completed] Keep nodata decisions in `NoDataPolicy`:

   - whether nodata pixels should be ignored in loss
   - which target ignore index to use
   - which image fill value to use

   `NoDataPolicy` now supports both HWC numpy arrays and CHW/HW torch tensor
   paths so the older repo-owned full-model datamodules and newer shared data
   scaffold use the same policy object.

3. [Completed] Pass the same ignore index to loss and metric code.

   Semantic workflow config already threads `ignore_nodata_in_loss` and
   `nodata_ignore_index` into datamodules, losses, and metrics. Instance
   comparison, finetuning, and checkpoint-sweep entry points now expose the
   same config fields and pass them into Toy and Graha datamodules. Instance
   object-detection losses do not consume a semantic-style ignore index
   directly, but the shared target preprocessing receives the same nodata
   policy.

4. [Completed] Verify semantic and instance behavior separately.

   Dataset audits passed for both semantic and instance segmentation, and the
   smoke test passed after the shared nodata-policy threading changes. Instance
   segmentation keeps task-specific target handling while sharing image-side
   nodata behavior.

   Current mismatch:

   - `lfm/full_model/all_tasks/utils` contains utilities that are not
     full-model/Graha-specific.
   - Examples include prediction cache writing/reading, plotting helpers, and
     comparison/evaluation helpers used by Toy and Graha workflows.
   - Moving workflow modules under `lfm/all_models/{task}/workflows` will make
     this mismatch more visible because all-model workflow code will still
     import shared behavior from a `full_model` namespace.

   Target direction:

   - Move truly shared utilities to `lfm/all_models/all_tasks/utils` or
     task-specific `lfm/all_models/{task}` modules.
   - Keep Graha-only utilities under `lfm/full_model`.
   - Keep Toy-only utilities under `lfm/toy_model`.
   - Preserve existing behavior by updating imports directly; do not create
     compatibility-only modules.

10. Validate the script cleanup without changing behavior.

   Validation should include:

   - import/syntax checks for touched modules
   - direct script `--help` checks where local dependencies permit
   - semantic and instance smoke tests
   - checkpoint sweep smoke tests for both semantic and instance segmentation
   - a structural scan confirming no `lfm/` package module imports from
     `scripts/python`

Deferred Decisions
------------------

Do not immediately move Toy workflow modules into `lfm/full_model/{task}`.

The desired model-family symmetry is not that Toy code lives under
`lfm/full_model`. The desired symmetry is:

- reusable Toy components live under `lfm/toy_model/{task}`
- reusable Graha/full-model components live under `lfm/full_model/{task}`
- shared Toy/Graha behavior lives under `lfm/all_models/{task}`
- importable workflow orchestration lives under `lfm/all_models/{task}/workflows`
- `scripts/python/{task}` contains executable entry points only

This is clearer than putting Toy implementation under `full_model`, and clearer
than keeping script-like finetuning orchestration under package modules.

Do not start with a full experiment framework rewrite.

The safer path is bottom-up:

1. Shared data IO.
2. Shared normalization and nodata policy.
3. Shared base dataset/datamodule.
4. Toy semantic migration.
5. Mirrored semantic/instance data migration.
6. Model adapters.
7. Experiment runners.

Validation Expectations
-----------------------

Each phase should include:

- Import/syntax checks for touched modules.
- Focused unit or smoke tests where available.
- A structural scan for sem/inst and Toy/Graha symmetry.
- No compatibility-only files left behind.
