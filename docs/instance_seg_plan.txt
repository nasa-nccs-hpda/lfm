Instance Segmentation Plan
==========================

Purpose
-------
This document tracks the work needed to bring lunar crater instance
segmentation into the full-model/Graha workflow. It is separate from the model
comparison plan because instance segmentation has a different label contract,
different plotting requirements, and may require a different model/task target.

Use this plan when working on .npz instance labels, bbox-safe transforms,
instance-aware datamodules, and true instance segmentation notebooks/scripts.
The end goal is a model that predicts separate crater instances, not only a
binary crater/background mask. The binary semantic-plus-shape workflow is a
compatibility checkpoint, not the final modeling target.

Related artifacts:
- lfm/full_model/datamodules: shared full-model datamodule code.
- notebooks/full_model: expected location for future interactive instance workflows.
- lfm/full_model/graha-lunar-fm: Graha/TerraMind/TerraTorch integration code.
- Existing semantic segmentation comparison code can be used as the notebook/script pattern.

Goal
----
Get a true lunar crater instance segmentation workflow running from split-folder
WAC data and .npz labels with mask, bboxes, and num_craters. The desired model
output should distinguish separate crater instances.

Resume Notes
------------
Instance segmentation work has reached a useful compatibility checkpoint:
Graha-style semantic segmentation plus crater boxes and shape loss can consume
the instance .npz labels. This proves the split-folder data, crop transforms,
and notebook/script scaffolding are usable, but it does not satisfy the final
true instance segmentation goal.

Current state:
- The label contract is confirmed.
- The full-model instance datamodule has been audited.
- The bbox crop utility has been updated so labels stored as COCO xywh are
  cropped/clipped correctly and emitted as xyxy crater_boxes for Graha shape
  loss.
- A lightweight instance sanity plotting helper exists and has been run on real
  data in the HPC environment.
- The split-folder instance dataset has passed a one-epoch smoke test through
  the Toy DINO and Graha binary semantic-plus-shape comparison workflow.

Current model target:
- True instance segmentation. The model should predict separate crater
  instances, not just crater/background pixels.
- The most likely first implementation path is Mask2Former-style supervision:
  per-instance binary masks plus class labels, optionally with boxes retained
  for plotting or auxiliary losses.

Recommended path:
- Treat the completed Option A workflow as a smoke test and baseline only.
- Move next to defining and implementing the true instance target contract.
- Prefer reusing the existing toy Mask2Former-style instance dataset/model
  patterns where they are compatible with the split-folder, crop-based
  full-model data standard.

Needed next:
- Define the exact batch contract for true instance training.
- Decide whether the first true instance model is the existing toy
  Mask2Former-style model, a TerraTorch-supported instance task, or a custom
  Lightning wrapper around Graha features.
- Update datamodules/notebooks/scripts around that contract.

Step 1: Confirm Label Contract [Completed]
------------------------------------------
Confirmed from example .npz labels and from preprocessing_inst_seg-Copy1.py:

- Label archive keys are mask, bboxes, and num_craters.
- mask has shape (300, 300), dtype uint8, and stores instance ids.
- mask value 0 is background.
- Positive mask values 1..N identify individual crater instances.
- bboxes has shape (N, 4), dtype float64.
- bboxes come from a COCO-style annotation JSON and are in xywh format:
  x_min, y_min, width, height.
- num_craters has dtype int64.
- In the inspected example, num_craters == len(bboxes) == 10.
- The preprocessing script creates a per-polygon binary mask, writes each
  polygon into a composite instance mask as instance id j + 1, appends each
  annotation bbox directly, and saves:
    mask=instance_mask
    bboxes=np.array(bboxes)
    num_craters=len(bboxes)

Important implementation notes:
- Preserve the integer instance ids for true instance segmentation.
- For semantic-plus-shape-loss experiments, derive a binary semantic mask with
  mask > 0, but do not overwrite the original instance mask in the dataset
  contract.
- Convert bboxes from xywh to xyxy internally when a model/task or transform
  expects corner coordinates.
- Cropping must update both the instance mask and xywh boxes consistently.
- The preprocessing script groups annotations by filename, so generated labels
  are expected to correspond to chips with at least one annotation. If we later
  include empty/background-only chips, the datamodule should handle:
    mask all zeros
    bboxes shape (0, 4)
    num_craters 0

Expected output:
- A documented batch contract for instance segmentation labels. Completed.

Step 2: Audit Current Instance Datamodule [Completed]
-----------------------------------------------------
Reviewed the full-model datamodule package under
lfm/full_model/datamodules, including lunar_segmentation_datamodule.py,
lunar_segmentation_dataset.py, instance_segmentation.py,
datamodule_utils.py, and the legacy toy Mask2Former dataset in
lfm/toy_model/inst_seg/iseg_dataset.py.

The minimum desired batch fields are:

- image: Tensor[C, H, W]
- mask: Tensor[H, W] or instance_masks depending on the selected model target
- crater_boxes or boxes: Tensor[N, 4] or list[Tensor]
- num_craters: int
- filename: str

Current full-model instance datamodule behavior:
- LunarInstanceSegmentationDatamodule uses the split-folder structure through
  the shared LunarSegmentationDatamodule base.
- It matches .tif chips to labels using the configured filename suffixes.
- It loads .npz labels through read_label_file(), preserving mask, bboxes, and
  num_craters.
- LunarInstanceSegmentationDataset defaults binarize_mask=False, so instance
  ids in the mask are preserved.
- Per-sample output currently includes:
    image
    mask
    filename
    crater_boxes
    num_craters
- The instance collate function stacks image and mask, keeps crater_boxes as a
  list of per-sample tensors, and stacks num_craters.

Important audit finding:
- The confirmed labels store bboxes as COCO xywh.
- The current center_crop() utility updates boxes as though they were xyxy:
    boxes[:, [0, 2]] -= left
    boxes[:, [1, 3]] -= top
    boxes[:, [0, 2]] = clamp(...)
    boxes[:, [1, 3]] = clamp(...)
- This is incorrect for xywh boxes because columns 2 and 3 are width/height,
  not xmax/ymax.
- Before using bboxes for training or shape loss, the crop transform must be
  corrected to explicitly handle xywh or convert xywh to xyxy before cropping.

Legacy toy instance dataset behavior:
- LunarCraterDatasetMask2Former loads .npz instance masks and converts the
  instance-id mask into Mask2Former-style:
    pixel_values
    mask_labels
    class_labels
    original_size
- It does not use the saved bboxes for training.
- It resizes image and mask to 304x304 rather than using the full-model crop
  standard.
- It expects a flat chips/labels directory and applies a random train/val split,
  so it is not directly aligned with the current split-folder full-model
  workflow.

Expected output:
- A clear list of what the datamodule already supports and what must be added.
  Completed.

Step 3: Decide Model Target [Completed]
-------------------------------------
Choose what "instance segmentation" means for the first working implementation.

Option A: Graha-style semantic segmentation plus crater boxes and shape loss.
- Uses semantic mask as the main target.
- Uses bboxes as auxiliary shape-loss metadata.
- Closest to the existing code path.

Option B: True instance segmentation.
- Predicts separate crater instances, masks, boxes, and labels.
- Requires an instance/detection task and model head.
- More work and higher integration risk.

Decision:
- The final target is true instance segmentation.
- The completed Option A path is retained as a compatibility smoke test and
  baseline, not as the main training direction.
- Toy DINO and Graha can consume instance labels as binary masks, but this does
  not replace the need for per-instance model outputs.

    faster-rcnn
    fcos
    retinanet
    mask-rcnn
    detr
    deformable-detr
    rf-detr
- ObjectDetectionTask accepts boxes_field, labels_field, and masks_field.
- The DETR implementation/tests include framework_masks=True, pred_masks,
  loss_mask, loss_dice, and mask targets.

Current recommendation:
- Use TerraTorch ObjectDetectionTask as the first true instance model path.
- Start with framework="mask-rcnn" because it is explicitly instance
  segmentation and uses the simpler TorchVision-style target contract.
- After the datamodule and plotting are stable, try framework="detr" or
  framework="deformable-detr" with framework_masks=True.
- Keep the existing toy Mask2Former-style code as a fallback/reference, not the
  primary first path.

Step 6: Implement Crop-Safe Label Transforms [Completed]
------------------------------------------------------
Cropping must update every label representation consistently.

For center crop or configured crop:

- Crop image.
- Crop mask.
- Shift boxes by crop offset.
- Clip boxes to crop bounds.
- Drop invalid or very small boxes.
- Update num_craters.

Expected output:
- A visual sanity check showing image, cropped mask, and cropped boxes agree.

Implementation status:
- center_crop() now accepts an explicit boxes_format.
- COCO xywh boxes are shifted into the crop frame, clipped to the crop bounds,
  filtered for valid size, and returned as xyxy boxes.
- This matches LunarShapeSegmentationTask.crater_shape_loss(), which expects
  crater_boxes in [x1, y1, x2, y2] pixel coordinates.
- plot_instance_batch_sanity() was added under lfm.full_model.utils for real
  data visual inspection.
- The plot helper was run in the HPC environment against actual instance labels.
- Boxes visually align with cropped instance masks, including crop-edge checks.
