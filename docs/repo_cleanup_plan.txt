Repository Cleanup Plan
=======================

Purpose
-------

This document tracks the cleanup work needed to move the full-model notebooks,
scripts, and reusable ML workflow code into a more maintainable structure.

Use this plan when moving runnable Python and shell entrypoints out of
notebooks/, extracting shared semantic/instance workflow helpers, and reducing
copy-paste between notebook, Python, and sbatch paths.

The intended end state is:

- notebooks/ contains only .ipynb files.
- scripts/python/ contains command-line Python entrypoints.
- scripts/shell/ contains sbatch and shell wrappers.
- lfm/full_model/all_tasks/ contains helpers shared by all ML tasks.
- lfm/full_model/sem_seg/ contains semantic-segmentation workflow helpers.
- lfm/full_model/inst_seg/ contains instance-segmentation workflow helpers.
- Notebooks and scripts import the same reusable implementation instead of
  duplicating behavior.

Cleanup Principles
------------------

- Move files mechanically before refactoring behavior.
- Keep notebooks as user-facing, linear workflows.
- Keep scripts as thin CLI wrappers with argparse and main().
- Keep reusable code inside the importable lfm package.
- Keep sbatch wrappers dumb: environment setup, logging, then call a Python
  script.
- Preserve existing command-line behavior where possible.
- Smoke-test each moved entrypoint before deeper extraction.
- Avoid changing model behavior during organization-only steps.

Step 7: Normalize Output and Log Layout [In-Progress]
------------------------------------------------

Make output behavior explicit and consistent:

- script-launched model outputs stay under scripts/outputs by default unless a
  user passes --base-output-dir.
- notebook-launched outputs can still stay under notebooks/full_model/outputs
  when the notebook config passes that base directory explicitly.
- shell logs go under scripts/logs.
- checkpoint folders use:
  - checkpoints/toy_model/
  - checkpoints/full_model/
- plots use:
  - plots/single_model/toy_model/
  - plots/single_model/full_model/
  - plots/comparison/
  - plots/instance_predictions/ when model-specific comparison is not involved

Acceptance checks:

- The new layout is documented in the scripts or plan.
- Existing smoke-test commands produce discoverable outputs.


Step 8: Smoke Test Moved Workflows [In-Progress]
-------------------------------------------

Run minimal checks after the move/refactor:

- semantic comparison notebook smoke test

- semantic checkpoint sweep small checkpoint subset
- instance fine-tuning notebook smoke test
- instance fine-tuning sbatch max_epochs=1

- instance comparison sbatch max_epochs=1

Acceptance checks:
