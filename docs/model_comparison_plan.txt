Model Comparison Refactor Plan
==============================

Purpose
-------
This document tracks the refactor work needed to compare the Graha/Lunar-FM
semantic segmentation model against the existing LFM Toy semantic segmentation
model using as similar an experiment as possible.

Use this plan when making structural changes to the comparison workflow,
including notebook/script parity, split-folder data handling, shared metrics,
side-by-side plots, checkpoint behavior, and sbatch execution. The plan is
intended to be updated as work progresses: mark one step [In-Progress], finish
and smoke-test it, then mark it [Completed] before moving to the next step.

Related artifacts:
- notebooks/full_model/semantic_seg_comparison.ipynb: interactive comparison workflow.
- scripts/python/semantic_seg/semantic_seg_comparison.py: sbatch-compatible comparison script.
- scripts/shell/semantic_seg/sbatch_semantic_seg_comparison.sh: Slurm wrapper.
- lfm/full_model: reusable Graha/full-model datamodules, utilities, and vendor integration.
- lfm/toy_model/sem_seg/lightning_wrappers: Lightning wrappers around the Toy semantic model.

Core Principles
---------------
- Maintain paired notebook and script artifacts for each workflow.
- The notebook is for interactive Jupyter development, debugging, plots, and
  inspection.
- The .py script contains the same training/evaluation logic in functions with
  a main() block so it can be launched with sbatch and run unattended.
- Keep shared logic in importable Python helpers where practical so the
  notebook and sbatch script do not drift.
- Move linearly: start one next step, finish and smoke-test it, then mark it
  completed before moving on.

Linear Refactor Plan
--------------------

1. [Completed] Reorganize full-model/Graha support code
   - Move reusable full-model datamodule code under lfm/full_model/datamodules.
   - Move reusable full-model utility and plotting code under lfm/full_model/utils.
   - Keep Graha/TerraMind vendor code under lfm/full_model/graha-lunar-fm.
   - Update imports in the Graha notebook and script to use the package paths.

2. [Completed] Add old toy semantic segmentation Lightning wrappers
   - Add comparison-specific wrappers under
     lfm/toy_model/sem_seg/lightning_wrappers.
   - Keep lfm/toy_model/sem_seg mostly intact as the source of model, loss, and
     dataset behavior.
   - Wrap the old DINOSegmentation model in a LightningModule.
   - Wrap explicit train/val/test split folders in a LightningDataModule.

3. [Completed] Bring the old toy workflow onto the split-folder data standard
   - Read explicit split directories:
       data/train/chips
       data/train/labels
       data/val/chips
       data/val/labels
       data/test/chips
       data/test/labels
   - Do not use random train/val splitting in the comparison workflow.
   - Keep semantic segmentation labels as .npy files.
   - Preserve the old model's existing band-filter behavior.
   - Keep normalize_inputs=False for the old model comparison baseline.
   - Save exact train/val/test file lists used by the dataloaders.
   - Add sanity checks for image shape, mask shape, mask values, foreground
     fraction, and matched filenames.

4. [Completed] Create old-model comparison run artifacts
   - Create notebooks/full_model/semantic_seg_comparison.ipynb.
   - Create scripts/python/semantic_seg/semantic_seg_comparison.py with matching logic.
   - Create scripts/shell/semantic_seg/sbatch_semantic_seg_comparison.sh.
   - Add timestamped output directory creation.
   - Save config snapshots and dataloader file lists under the run output dir.
   - Add ./data symlink setup/check behavior to both notebook and script.

5. [Completed] Smoke-test the old-model notebook and sbatch script
   - Run the notebook for 1 epoch.
   - Run the sbatch/.py script for 1 epoch.
   - Confirm batches load, loss computes, checkpoints save, and both workflows
     can run outside the interactive notebook.

6. [Completed] Change the old toy comparison baseline to 256x256 crop inputs
   - Add an explicit spatial transform option to the toy comparison data path:
     resize or crop.
   - Implement crop behavior so images and labels use the same crop window.
   - Set the comparison baseline to crop to 256x256 to better match the
     Graha/full-model input path.
   - Keep normalize_inputs=False unless we deliberately define a second
     normalization variant.
   - Update the notebook, script, saved config, and sanity summary to report
     crop behavior clearly.
   - Smoke-test notebook and sbatch for 1 epoch after this change.

7. [Completed] Refine the comparison notebook to mirror the original semantic
   segmentation notebook
   - Reorder and rename cells to match the original notebook's interactive flow
     as closely as practical.
   - Keep the new split-folder, symlink, timestamped-output, and script-shared
     logic.
   - Avoid duplicating large logic in notebook cells when the script helper
     functions already provide it.

8. [Completed] Restore validation visualization for the old toy comparison
   - Add validation plotting for both notebook and sbatch script runs.
   - Match the original semantic segmentation notebook's expected visual
     debugging behavior as closely as practical.
   - Save plots into the timestamped output directory.
   - Ensure a 1-epoch run produces at least one validation plot.

9. [Completed] Refactor the comparison notebook for side-by-side model comparison
   - Keep training jobs separate for the toy model and Graha/full model.
   - Load one trained model at a time for inference to avoid holding both large
     models in VRAM/RAM simultaneously.
   - Save per-sample predictions, probabilities/logits if useful, and metadata
     into the timestamped output directory.
   - Build side-by-side notebook cells that load saved predictions from both
     runs and plot the same samples together.
   - Prefer a lightweight prediction-cache format so the notebook can compare
     results without rerunning both models.
   - Only consider simultaneous model loading later if the one-at-a-time path
     is too slow and measured VRAM usage shows it is safe.

10. [Completed] Add shared evaluation metrics
   - Build evaluator helpers that can consume either model through a small
     prediction adapter.
   - Evaluate both models on the same validation/test split.
   - Compute the same metrics:
       pixel accuracy
       foreground precision
       foreground recall
       foreground F1
       IoU
       predicted foreground fraction
       ground-truth foreground fraction
   - Save metrics as CSV and/or JSON.

11. [Completed] Add side-by-side Graha vs toy plots
    - For the same validation/test samples, save panels with:
        input RGB composite
        ground truth
        toy-model prediction
        Graha prediction
        toy-model overlay
        Graha overlay
    - Use the same thresholding, colors, sample order, and filenames.

12. [Pending] Run the 100-epoch comparison
    - Submit the toy-model script with sbatch.
    - Submit the Graha/full-model script with sbatch.
    - Run shared evaluation on the same held-out split.
    - Compare metrics and inspect side-by-side plots.
