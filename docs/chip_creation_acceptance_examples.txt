CHIP CREATION ACCEPTANCE EXAMPLES
=================================

Purpose
-------
This file keeps concrete seed values for the C0 acceptance contract in
chip_creation_modernization_plan.md. It is a reference for local fixtures,
notebooks, and Explore/HPC validation. Paths and training-sample filenames
marked "illustrative" are not repository files and must be resolved against
the validation dataset before a run.

Identity rule used by every example
-----------------------------------
The full normalized stem, including row/column offsets, is the sample and label
key. For example:

  image:  M1187363083CE_r0_c0_input_wac_chip.tif
  label:  M1187363083CE_r0_c0_label.npy
  sample: M1187363083CE_r0_c0
  WAC product selector: M1187363083CE

The first filename component is a product selector only for built-in WAC and
NAC sources. It is not a unique sample ID. Other modalities default to
all_intersecting and use their full normalized filename stem for label pairing.
Two requests such as M1187363083CE_r0_c0 and M1187363083CE_r300_c0 are valid
distinct samples that reuse the M1187363083CE product selector and resolve
different labels.

Common synthetic target-grid convention
---------------------------------------
Where an example does not point to an existing reference TIFF, use a 300 x 300
north-up target grid in the repository IAU:30100 geographic CRS. The AOI bounds
and dimensions must be converted into a complete affine transform before label
preflight. These geographic grids are contract fixtures, not a recommendation
that every production dataset store final chips in degrees.

Negative example A: label identity or shape mismatch
----------------------------------------------------
Given the Example 1 request, any label that normalizes to a different full
sample ID, or whose mask is not exactly 300 x 300, raises LabelMismatchError.
Tiling is not invoked, no final chip or copied label is written, the failed
request and its planned split remain in the manifest, and the batch continues.

Boundary example B: antimeridian acquisition
---------------------------------------------
Status: synthetic contract fixture.

  logical AOI: ul_lat=1.0, ul_lon=179.8, lr_lat=0.8, lr_lon=180.2
  query part 1: ul_lat=1.0, ul_lon=179.8, lr_lat=0.8, lr_lon=180.0
  query part 2: ul_lat=1.0, ul_lon=-180.0, lr_lat=0.8, lr_lon=-179.8

The two public tiling results are combined and deduplicated structurally, then
reprojected to one final target grid. A longitude span of 180 degrees or more
is rejected as ambiguous.

Negative example C: unsupported polar coverage
-----------------------------------------------
Any densified target footprint extending north of +82 degrees or south of -82
degrees fails before tiling with unsupported_polar_coverage. The 80-to-82
degree numbered-LTM overlap requires its dedicated regression before use.

Default split example
---------------------
Use MixedPercentageNumberSplitConfig with:

  fixed targets:       test=100 samples
  fixed priority:      test
  remaining ratios:    train=0.90, val=0.10, test=0.0
  group key:           a scientifically justified product/site/campaign/AOI key
  seed:                explicit dataset-creation seed

Whole split groups remain atomic. If exactly 100 test samples cannot be
realized, record the requested and realized counts and emit a warning; do not
fail the batch. Percentage assignment applies only to the groups remaining
after fixed-target assignment.
