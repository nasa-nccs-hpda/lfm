Goal: compare the Graha/Lunar-FM semantic segmentation model against the
existing LFM toy semantic segmentation model using as similar an experiment as
possible.

Core principle:
- Maintain paired notebook and script artifacts for each workflow.
- The notebook is for interactive Jupyter development, debugging, plots, and
  inspection.
- The .py script contains the same training/evaluation logic in functions with
  a main() block so it can be launched with sbatch and run unattended.
- Keep shared logic in importable Python helpers where practical so the
  notebook and sbatch script do not drift.

Plan:

1. Bring the old toy semantic segmentation code up to the new data standard
   - Add comparison-specific Lightning/DataModule wrappers under
     lfm/toy_model/sem_seg/lightning_wrappers rather than rewriting the
     existing toy_model driver.
   - Keep lfm/toy_model/sem_seg mostly intact and treat it as the source of the
     model, loss helpers, and existing behavior.
   - The comparison DataModule should read explicit split directories:
       data/train/chips
       data/train/labels
       data/val/chips
       data/val/labels
       data/test/chips
       data/test/labels
   - Do not use random train/val splitting for this comparison workflow.
   - Keep semantic segmentation labels as .npy files.
   - Keep image resizing to the old model's expected 304x304 input size.
   - Keep normalize_inputs=False for the old model comparison baseline.
   - Preserve the old model's existing band-filter behavior.
   - Save the exact train/val/test file lists used by the dataloaders.
   - Add sanity checks for image shape, mask shape, mask values, foreground
     fraction, and matched filenames.
   - The comparison LightningModule should wrap the old DINOSegmentation model,
     reuse the old loss helpers, and reproduce the old optimizer/scheduler
     behavior where practical.

2. Create comparable old-model artifacts
   - Copy lfm/notebooks/toy_model/semantic_seg_train.ipynb to a new comparison
     notebook under notebooks/full_model.
   - Create a matching .py script for the old semantic segmentation workflow
     under lfm/full_model.
   - Add an sbatch wrapper under notebooks/full_model for the .py script.
   - Do not overwrite the original toy_model semantic_seg_train.ipynb.

3. Standardize output directories
   - Use timestamped output dirs for both workflows.
   - Save checkpoints, plots, config snapshots, losses, metrics, and file lists
     under the run output dir.
   - Keep notebook output and sbatch output naming consistent.

4. Align high-level training configuration
   - Run 100 epochs for both workflows.
   - Use batch size 16 if it fits for both.
   - Use one GPU initially for both.
   - Use the same train/val/test split folders.
   - Use the same 7 WAC bands where possible.
   - Keep optimizer/loss/model differences documented unless we deliberately
     create a second controlled variant.
   - Use the same plotting cadence, likely every 10 epochs plus final.

5. Keep model-specific behavior explicit
   - Graha uses its current datamodule-side per-band z-score normalization.
   - The old toy model comparison baseline keeps normalize_inputs=False.
   - The old toy model resizes to 304x304.
   - The Graha model uses its 256x256 crop path unless we later choose to test
     a controlled size variant.
   - Document model, checkpoint, input adaptation, decoder, loss, optimizer,
     scheduler, image size, and preprocessing in each output dir.

6. Create shared evaluation code
   - Build evaluator helpers that can consume either model through a small
     prediction adapter.
   - Evaluate both models on the same validation/test split.
   - Compute the same metrics:
       pixel accuracy
       foreground precision
       foreground recall
       foreground F1
       IoU
       predicted foreground fraction
       ground-truth foreground fraction
   - Save metrics as CSV and/or JSON.

7. Create side-by-side plots
   - For the same validation/test samples, save panels with:
       input RGB composite
       ground truth
       old-model prediction
       Graha prediction
       old-model overlay
       Graha overlay
   - Use the same thresholding, colors, sample order, and filenames.

8. Smoke test before long runs
   - Run both workflows for 1 epoch.
   - Confirm batches load, losses compute, checkpoints save, plots save, and
     shared evaluation runs.
   - Confirm the sbatch scripts work without relying on an interactive Jupyter
     session.

9. Run the 100-epoch comparison
   - Submit the old-model script with sbatch.
   - Submit the Graha script with sbatch.
   - Run shared evaluation on the same held-out split.
   - Compare metrics and inspect side-by-side plots.

Preferred implementation order:
1. Add comparison-specific DataModule and LightningModule wrappers under
   lfm/toy_model/sem_seg/lightning_wrappers for the old toy semantic
   segmentation model.
2. Create the old-model comparison notebook.
3. Create the matching old-model .py script and sbatch wrapper.
4. Add shared evaluation and side-by-side plotting helpers.
5. Run 1-epoch smoke tests.
6. Launch 100-epoch runs.
